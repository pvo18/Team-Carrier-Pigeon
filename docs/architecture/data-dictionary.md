# Data Dictionary

**What this file describes**:

- Every column in the two files we model from, `residents.csv` and `weekly_panel.csv`, and what we do with it: model feature, target, split / join key, filter-only, fairness-audit-only, or dropped. Provider definitions live in `data/provider-docs/DATA_DICTIONARY.md` after running `scripts/set-up-repo.py`.
- The exact columns written to `data/processed/` by `preprocessing/preprocess.py`.
- The reason each column is kept or dropped, so the feature set can be reviewed for data leakage. **The rule: a column can be a model input only if its value is known at the start of the week being predicted.** Anything computed over the whole tenancy, or recorded at or after move-out, fails it.

Column decisions made 2026-10-20 (`[T]`); `site`, the band columns, `work_distance_mi`, and `rent_to_income_ratio` are no longer pending. Anything still marked `pending` or `[S]` is a team decision.

**Source tags** (in the Notes columns):

## Model Features

The processed file holds these columns as raw values. Encoding, scaling, and filling in missing values happen in the **model pipeline**, fit on the training households of each fold or bootstrap sample only (PRE-4). Every numeric feature with blanks also gets a 0/1 `<column>_missing` indicator and a median fill computed on the training split. [S]

**Feature budget:** 10 features below, plus up to 7 `_missing` indicators. The provider's README (limitation 7) says 125 move-outs support roughly 6–12 covariates before overfitting, so every column has to earn its place: no banded copies of a raw column, no two measures of the same route. [T]

**Takeaways for the report:**

- 72% of households are still active at the extract date (censored), so most tenancies have no observed ending.
- The longest observed tenancy is 46 weeks (`week_index` max). The proposal's 52-week horizon can't be checked against real outcomes (EVAL-6).
- Income and commute are each blank for about 1 in 6 households, and rent-to-income for about 1 in 3.

**Provider dictionary vs. the actual files** (checked 2026-10-15; facts only):

- All column names in the CSV headers match the provider's dictionary, and the row counts match (455 / 7,566 / 6,731).
- `residents.lease_status`: 6 raw values, not 5. `Moved-Out ` and `Future Move In ` carry a trailing space (65 and 7 rows), alongside 45 rows of `Moved-Out` without one.
- `residents.lease_status` vs `is_active`: 11 `Closed Lease` and 1 `Moved-Out ` rows have `is_active = 1`; 5 `Active` rows have `is_active = 0`.
- `residents.income_quality_flag`: provider lists `ok`, `unit_inferred`, `income_missing`, `implausible_after_normalisation`, `no_application`. The file has no `unit_inferred`, and has two undocumented values: `ok_unit_ambiguous` (122) and `unit_reconciled` (104).
- `residents.income_basis`: both `Bi-Weekly` (26) and `BiWeekly` (48) appear.
- `residents.sc_eviction_history`: provider says Crosby only, but Willis Lakes has 245 non-blank values.
- `residents.discount_group`: the file has only `None` (277), `Government Employees` (1), and blank (177).
- `weekly_panel.delinquent`: documented as 0/1; 755 rows are blank, exactly the weeks of the 64 households with no `weekly_rent`.
- `weekly_panel` covers 444 households, not 455; `censored_this_week` therefore sums to 319, not 330.
- Band labels are written differently from the dictionary (e.g. `45min+` vs "45+ min"). Same bins.
